## 2. "一切都是任务"原则

### 2.1 统一原则，不需要例外

**"一切都是任务"是一个统一原则，不需要引入"系统级操作"或"系统任务"这样的特殊分类。**

mem0ress 的核心设计哲学是：所有工作单元都是任务。系统操作也不例外。

### 2.2 Go 的类比

```go
// Go 的并发模型：一切都是 goroutine
// 包括调度器本身也是用 goroutine 实现的

// 用户定义的并发任务
go func() { /* 实现 OAuth */ }()

// 系统级任务（调度器）
go scheduler()

// 没有"系统级操作的特殊分类"
// 只有"被调度的任务"和"调度其他任务的任务"
```

### 2.3 类比操作系统

在操作系统级别，"任务"（task/thread/process）是一个通用概念：
- 用户进程是任务
- 内核调度器也是任务
- 没有因为"系统级"就引入特殊例外

## 4. 循环依赖问题的解决

### 4.1 问题描述

如果"一切都是任务"是绝对原则：

```
任务 A 开始执行
    ↓
需要审计任务 A 自身
    ↓
审计任务本身是任务 B
    ↓
需要审计任务 B 自身
    ↓
...
```

这似乎是一个循环依赖陷阱。

### 4.2 解决：层级关系而非同层循环

**实际上不存在循环依赖，因为检验形成层级关系，不是同层循环。**

```
用户任务（实现 OAuth）
    │
    └── 验证任务（Tier 0/1/2/3）
            │
            └── 验证验证任务（Judge Agent）
                    │
                    └── ...
```

**Judge Agent 是一个验证任务**，它的职责是验证其他任务的对齐状态。它和其他任务之间是**层级关系**（验证者与被验证者），不是**同层循环关系**。

### 4.3 核心洞察

> 验证者与被验证者之间是单向的层级关系，不存在循环。
>
> Judge Agent 验证任务 A，但不需要验证自己（验证自己是一个不同的任务）。

### 4.4 类比

```
编译器验证代码语法
    ↑
    │ 谁来验证编译器？
    │
    └── 编译器的编译器（元编译器）验证编译器本身
            ↑
            │ 谁来验证元编译器？
            │
            └── ... （实际应用中，这个链条不需要无限延伸）
```

## 5. Judge Agent 的定位

### 5.1 Judge Agent 是一个任务

按照"一切都是任务"原则：

- **Judge Agent 是一个标准的任务**
- 它的 Picture：判断被验证任务的产出是否达到 Picture 描述的对齐状态
- 它的 Requirements：提供 aligned / deviation 结果
- 它的 Constraints：独立判断，不受主 Agent 影响

### 5.2 Judge Agent 的工作性质

- **任务**：语义对齐判断（Picture vs Artifact）
- **触发**：按需（不是每轮次）
- **输入**：被验证任务的 Picture + 实际产出
- **输出**：aligned / deviation + 原因
- **每次验证是独立的**

### 5.3 持久性问题

**Judge Agent 是否需要长时保活，是部署决策，不是架构决策。**

| 选项 | 场景 | 考量 |
|------|------|------|
| **按需 spawn** | Claude Code | 简单，冷启动延迟可接受 |
| **会话级复用** | Hermes | 减少冷启动开销，保持轻量 |
| **长时保活** | 企业级、高并发 | 速率限制、审计日志、并发控制 |

## 6. 最终决策

### 6.1 所有 Tier 统一使用 Agent 执行

**决策**：如果 token 消耗压力不大，Tier 0/1/2/3 全部使用 Agent 执行。

**理由**：
1. **简化判断逻辑**——不需要区分"机械检查"和"判断检查"
2. **一致性**——Tier 0 也不一定只是规则式的
3. **减少条件分支**——避免"是否需要 Agent"的判断开销
4. **统一执行模型**——更容易实现和理解

**代价**：Token 消耗增加。

### 6.2 Judge Agent 的定位

- **是一个标准任务**，遵循"一切都是任务"原则
- **形成层级关系**，不存在循环依赖
- **持久性由宿主决定**，不是 mem0ress 规定的

### 6.3 分层执行模型（简化版）

由于所有 Tier 都使用 Agent 执行，威胁模型简化：

```
┌─────────────────────────────────────────────────────┐
│  mem0ress 接口契约（跨宿主通用）                       │
│  - Tier 0/1/2/3 的触发时机                           │
│  - Tier 0/1/2/3 的输入输出格式                        │
│  - 检验结果对 Agent 的呈现方式                        │
└─────────────────────────────────────────────────────┘
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
   ┌─────────┐      ┌─────────┐      ┌─────────┐
   │  L0     │      │  L1     │      │  L2     │
   │ 内省模式 │      │ 分离模式  │      │ 隔离模式  │
   └─────────┘      └─────────┘      └─────────┘
```

| 模式 | Judge 持久性 | 适用场景 |
|------|-------------|---------|
| **L0：内省模式** | 按需 spawn | Claude Code、探索性任务 |
| **L1：分离模式** | 会话级复用 | Hermes、标准 Agent 系统 |
| **L2：隔离模式** | 长时保活 | 企业级应用、高危任务 |
