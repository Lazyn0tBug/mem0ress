## 类别说明

- **矛盾**: 同一事实有两种互斥描述，必须裁定其一
- **重复**: 内容相同但文字略有出入，只需保留一处
- **歧义**: 同一术语指代两个不同概念，需要区分命名
- **行文**: 语义正确但表述冗余或节奏问题

## 矛盾类（必须解决）

### 矛盾-A: "认知对齐平面"定义飘忽

**位置:** 1.3节 vs 4.2节

- 1.3节：整个系统名为"认知对齐平面"（作为 mem0ress 的别名）
- 4.2节：Plane 是 Status Plane 的简称，只是系统的一个组件

**两种用法在全文中交替出现，读者无法建立稳定心智模型。**

**裁定方案:**
- "认知对齐平面" → 专指整个系统（mem0ress 本身）
- "状态平面"（Status Plane）→ 专指 L1 的纯展示组件
- "数据平面"（Data Plane）→ 专指代码/文档的 commit ID 映射表

---

### 矛盾-B: 三层物理隔离与三层架构说的是两回事

**位置:** 1.3节 vs 7.1节

- 1.3节三层：CPU(LLM) / RAM(mem0ress) / Disk(外部知识)
- 7.1节三层：L1 认知网关 / L2 认知基座 / CPU(LLM)

明明画了架构图，却把 LLM 画成 CPU 放在架构之外。三层物理隔离又把 LLM 当 CPU 放在里面。L1 认知网关和 CPU 的关系始终没讲清楚。

**裁定方案:**
- 统一为一幅图，CPU = LLM，始终在架构内部
- 三层物理隔离（CPU/RAM/Disk）是对 L1/L2/L3 的**功能分类描述**，不是独立的另一套分层
- L1 = CPU + Plane + Harness（处理枢纽）
- L2 = mem0ress 本体（工作内存/状态层）
- L3 = 外部知识库（磁盘/客观数据）

---

### 矛盾-C: Harness / Judge Task 的触发主体模糊

**位置:** 6.2节 Tier 3 vs 7.1节 Harness Engine

- 6.2节 Tier 3：主 Agent spawn 一个 Judge Agent 来验证
- 7.1节 Harness Engine：说是 L1 的组件，独立执行三层验证

**这两段描述的是同一套机制，但触发主体一会儿是 Agent，一会儿是 mem0ress 自己，互相矛盾。**

**裁定方案:**
- Agent 是触发主体（显式调用 `verify_task()` 触发 Harness）
- Harness Engine 是 mem0ress L1 的工具实现，不是自主运行的常驻进程
- Judge Task 是 Tier 3 的执行方式，由 Agent spawn，Harness Engine 负责协调其输入输出

## 歧义类（需要区分）

### 歧义-F: "状态平面"一词指代两个层次

**出现位置:**
- 1.3节"动态平面分离"里：指整个 Status Plane 视图（广义的 Agent 可见工作区）
- 6.3节"状态平面"里：缩窄成"纯展示当前状态的组件"（狭义的 L1 组件）

**处理:**
- "状态平面（广义的）" → 改称"**认知态势**"（Agent 每次唤醒时看到的完整上下文）
- "状态平面（狭义的）" → 保留"状态平面"，专指标注了 Status/Todos/Gotchas 的 L1 展示组件
- 在第一次出现时加注说明，防止后续歧义
