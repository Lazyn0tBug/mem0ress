# 示例集 — mem0ress Protocol Examples

> 每个案例展示不同任务类型在 mem0ress 协议下的完整执行流程。

---

## 案例概览

| 文件 | 类型 | 侧重点 |
|------|------|--------|
| `oauth-sso.md` | 软件交付 | 完整生命周期：失败 → 修正 → 通过；Tier 2 `verify_cmd`；gotchas 记录 |
| `whitepaper.md` | 认知交付 | PRC 推导；Phase 分组 Todo；Terminology 一致性检查；Tier 3 语义对齐 |

## 共同设计原则

### task.md 结构

```yaml
---
id: <auto-generated>
type: task
status: <status>
---

# <任务名称>

## Picture

> <语义成功状态 — 利益相关者感知到的结果>

## Requirements

- [x] R-1: <描述>（`verify_cmd: <命令>`）
- [ ] R-2: <描述>

## Constraints

- C-1: <绝不允许>
- C-2: <绝不允许>

## Todos

### Phase 1 — <名称>
- [ ] T-1: <机械步>
```

### Verify 层级职责

| Tier | 检查内容 | 执行方式 |
|------|---------|---------|
| Tier 0 | Constraints 违反 | 扫描 session.md / gotchas.md |
| Tier 1 | Todo & Subtask 完成 | 读取 task.md |
| Tier 2 | Requirements 满足 | 运行 `verify_cmd` |
| Tier 3 | 语义对齐（条件触发） | Verify Agent 推断 |

### CLI 命令速查

```bash
mem0 init                              # 初始化 .cap/
mem0 create --picture "..."             # 创建任务（task_id 自动生成）
mem0 status                            # 查看所有任务
mem0 update --content "..."            # 追加 session 快照
mem0 done [task_id]                    # 触发 Verify，COMPLETED
mem0 abandon [task_id]                  # 废弃任务
mem0 report [task_id]                   # 查看 Verify 报告
```

### Skill 命令

```bash
/cap create     # 语义初始化
/cap recover    # 恢复任务认知
/cap status     # 查看状态平面
/cap snapshot   # 追加认知增量
/cap gotcha     # 记录关键发现
/cap verify     # 请求 Verify 验证
/cap decide     # 读取判决，决定下一步
/cap close      # 语义关闭验证
```

## 案例索引

### oauth-sso.md — 软件交付（完整生命周期）

**任务：** 为企业内部工作台实现 OAuth 单点登录

**特色：**
- 完整的 Turn 时序（Turn 1.1 → 1.2 → 2.1 FAILED → 1.3 修正 → 2.2 PASSED）
- Tier 2 `verify_cmd` 执行 pytest
- gotchas.md 记录性能优化的教训
- 展示"失败 → 修正 → 通过"的完整 Verify 交互

---

### whitepaper.md — 认知交付

**任务：** 撰写一份 AI Agent Framework 白皮书

**特色：**
- Picture 先于 Requirements/Constraints 的推导顺序
- Phase 分组 Todo（R-1~R-6 对应 Research/Architecture/Writing/Validation）
- Terminology 一致性检查（glossary scan）
- Tier 3 语义对齐（Picture Claims 映射）
- "绝不允许"强约束语言

---

### website.md — 软件交付（多类验证）

**任务：** 制作 mem0ress 官方网站

**特色：**
- Tier 2 量化验证（Lighthouse Performance ≥ 90、responsive test）
- CI/CD 集成验证
- 多类 Constraints（C-1~C-5，涵盖内容/技术/部署）
- Tier 2 自动验证（R-2 responsive test、R-3 Lighthouse）
- deployment 验收

---

## 关键区别：认知交付 vs 软件交付

| 维度 | 认知交付（白皮书） | 软件交付（OAuth/网站） |
|------|-----------------|---------------------|
| 主产出 | cognition artifact | software artifact |
| Tier 3 权重 | 极高 | 中 |
| Tier 2 权重 | 中 | 极高 |
| Failure 风险 | semantic incoherence | implementation inconsistency |
| Verify 重点 | worldview consistency | user-facing coherence |
| Requirements 验证 | glossary scan、word count | pytest、Lighthouse、CI |
