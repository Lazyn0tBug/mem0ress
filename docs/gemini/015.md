# mem0ress: 认知态势感知系统架构蓝图
版本: v2.0 (极简核心版) | 定位: 基于纯文本的心智模型与自主 Agent 认知引擎

## 1. 核心哲学 (Core Philosophy)

mem0ress 摒弃了传统的“被动记忆检索（RAG）”理念，将记忆视为认知的一部分，始终站在目标和任务本身来理解记忆。

认知而非记忆： 不记录流水账对话，只记录推进目标的“状态突变（Cognitive Delta）”。

目标锚定（Goal-Anchored）： 没有悬空的数据孤岛。所有激活的信息必须严格服务于当前活跃的任务和目标画面（Picture）。

无数据库的完备文档集： 彻底抛弃向量数据库与复杂检索算法。我们不需要大模型之上的大模型，整个系统就是一个结构完备、语义清晰的 Markdown/YAML 文件集合。

系统级卸责（Separation of Concerns）： 明确系统边界。代码沙箱安全性、多线程并发控制不属于 mem0ress 的管辖范畴，交由宿主操作系统和执行环境解决。

## 2. 宏观架构模型 (L1-L2 Architecture)

在整个认知模型中，系统被极致精简为完全解耦的两层, L3属于外部内容：

  * L1 - 认知执行层 (The Mind / Execution):
  
  解决“如何构建认知”。
  
  包含 Agent 及其调用的工具链（Tools）。它负责阅读地图、处理意图、执行逻辑，并在必要时唤醒 Harness 进行质检。
  
  * L2 - 数据状态层 (The Data / mem0ress):
  
  解决“如何记录数据”。
  
  完全基于本地的纯文本文件系统。它是一个被动的介质，负责提供清晰的目录树拓扑、存储任务骨架（Tasks）和认知增量（Info）。
    
  3. L3 - 泛化知识层 (The Disk / External KB):
  
    * 外部的向量数据库、API 文档、全网搜索库。
    * Agent 遇到“认知缺口”时，主动向此层索取客观素材。
  

## 3. 数据拓扑：目录即地图 (Data Topology)

放弃扁平化与过度复杂的 Tag 过滤，回归最符合人类直觉的目录树（File Tree）模型。根目录下的文档通过描述精确对应到相应的子文档。

### 3.1 目录结构

```plaintext
.mem0ress/
├── tasks/
│   ├── task1_auth_module/
│   │   ├── index.md          # Task 1 的核心锚点与 Picture
│   │   ├── subtask1_jwt.md   # 子任务 1：具体实现与认知
│   │   └── subtask2_oauth.md # 子任务 2：具体实现与认知

│       └── index.md

└── inbox.md                  # 灵感中转站：未格式化的游离想法
```

## 4. 认知核心工作流 (Cognitive Workflow)

系统围绕认知的“生命周期”展开，分为三大核心动作：

### 4.1 构建认知 (Build Cognition)

冷启动装载： Agent 唤醒时，L1 执行层扫描 L2 目录树，提取出带有路径、标题和极简描述的层级大纲（Outline）。

按需深入： Agent 依据目标（Picture），通过调用文件读取工具（如 read_file）主动抓取对应的子任务或信息文档，在当前会话中动态拼装出态势感知上下文。

### 4.2 记录认知 (Record Cognition)

绝对覆写原则： Agent 在更新状态或写入决策时，不进行复杂的后台 Merge，直接采用覆写（Overwrite）操作。

冲突检测机制： 覆写操作前，L1 工具链强制检查文件是否已存在或被外部修改。若存在冲突，向 Agent 发出警告并附带现有内容摘要，由 Agent 决定是否强制覆写或进行人工干预。

### 4.3 检验认知 (Verify Cognition / Harness)

当 Agent 更新 Task 的 Todo 列表（- [x]）或声明任务完成时，触发外置的 Harness 流程[cite: 2]：

* Tier 1 (机械状态检查): 从 Todo 列表中获取子任务状态[cite: 2]。若存在未勾选的 - [ ]，直接阻断，要求 Agent 继续执行[cite: 2]。
* Tier 2 (严格指标验证): 运行 requirements 中的 validator 脚本[cite: 2]。（注：脚本运行沙箱由系统环境提供，Harness 仅捕获执行结果）
* Tier 3 (语义画面对齐): 结合上下文，调用 LLM 独立评估产出是否满足外置的 Picture 语义[cite: 2]。

失败补丁反哺： 校验失败不只是报错，而是生成包含 Error Log 的高优先级 Info 文件（Failure Patch），要求 Agent 重新“构建认知”并重试。[cite: 2]

## 5. 预期系统优势
通过实施这套蓝图，系统将实现：

极度高能效的上下文： 喂给 LLM 的永远是被浓缩、被目标过滤过的核心状态，极大降低 Token 消耗和幻觉率[cite: 2]。

工程级的鲁棒性： 外部的 Harness 打断了 Agent 可能产生的逻辑死循环，使其具备了“自我纠错”的系统级保障[cite: 2]。

完全透明的掌控感： 没有任何黑盒数据库。开发者可以用 VS Code 随时打开 .mem0ress/，像阅读项目的源代码一样阅读 AI 的“心智状态”[cite: 2]。
