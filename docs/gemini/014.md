这份文档汇总了我们对“数据汤”、“大模型认知边界”以及“执行与监督解耦”的所有深度推演，确立了系统的物理边界、数据结构和核心运转机制。它可以作为整个项目的顶层设计规约（Architecture Specification）。

# mem0ress: 认知态势感知系统架构蓝图

版本: v1.0 | 定位: 基于纯文本的心智模型与自主 Agent 操作系统内核

## 1. 核心哲学 (Core Philosophy)

mem0ress 摒弃了传统的“被动记忆检索（RAG）”理念，转而为 AI Agent 构建具有前瞻性的心智模型（Mental Model）。

  * 认知而非记忆： 不记录流水账对话，只记录推进目标的“状态突变（Cognitive Delta）”。
  * 目标锚定（Goal-Anchored）： 没有悬空的数据孤岛。所有激活的信息必须严格服务于当前活跃的任务和目标画面（Picture）。
  * 三层物理隔离（The CPU-RAM-Disk Model）： Agent 作为处理枢纽（CPU），mem0ress 作为高频强状态的工作内存（RAM），外部向量数据库作为无状态的客观硬盘（Disk）。硬盘数据绝不直接污染内存，必须经由 Agent 蒸馏内化。

## 2. 宏观架构模型 (Macro Architecture)

系统在逻辑上被划分为完全解耦的三层，Agent 作为唯一跨层交互的实体。

  1. L1 - 瞬态执行与评估层 (The Mind):
  
    * Agent (执行者): 负责理解、编码、调用工具和知识蒸馏。
    * Plane (前额叶): 动态生成的工作区，维持当前的全局态势感知。
    * Harness (元认知): 独立的外部监督程序，负责验收与纠偏。
  
  2. L2 - 状态与经验层 (The RAM / mem0ress):
  
    * 完全基于本地的纯文本（Markdown + YAML）文件系统。
    * 存储任务骨架（Tasks）、热点经验（Hot Info）和全局收件箱（Inbox）。
  
  3. L3 - 泛化知识层 (The Disk / External KB):
  
    * 外部的向量数据库、API 文档、全网搜索库。
    * Agent 遇到“认知缺口”时，主动向此层索取客观素材。
  
## 3. 数据拓扑与 Schema 定义 (Data Topology)

保持极简的扁平化文件系统。取消深层目录树，转而使用 Tags 进行多维软链接。

### 3.1 目录结构

```plaintext
.mem0ress/
├── tasks/            # 意图锚点：所有的任务节点 (仅存 Root Task)
├── info/             # 认知增量：所有的决策、报错、蒸馏知识
├── inbox.md          # 灵感中转站：未格式化的游离想法与待处理项
└── .plane.yaml       # 瞬态工作台：AI 每次操作前动态生成，代表此刻的认知 (不持久化)
```

### 3.2 Task: 意图锚点 (tasks/task_<id>.md)

Task 是 Agent 存在的理由。禁止为子任务创建独立文件，子任务通过 Markdown Todo List (- [ ]) 管理。Task 头部的 YAML 定义了 Harness（质检器） 的验收标准。

````markdown
---
id: task_user_auth
type: task
status: in-progress      # created | in-progress | completed | abandoned
tags: [auth, security, oauth]

# 外部任务级 Harness (评估台) 配置
harness:
  picture: "用户能够顺畅地使用邮箱和 Google OAuth 登录，UI 交互符合设计规范且无卡顿报错。"
  requirements:
    - rule: "核心逻辑测试覆盖率 > 80%"
      validator: "npm run test:auth"  # 可执行脚本
    - rule: "响应延迟 < 200ms"
---
# 实现用户鉴权模块

## Sub-tasks (Harness Tier 1)
- [x] 开发基础登录 API
- [x] 集成 Google OAuth
- [ ] 编写 Auth 守卫中间件

## 认知日志
- 2026-05-01: OAuth 集成完毕，准备处理中间件拦截逻辑。
````

### 3.3 Info: 认知增量 (info/info_<id>.md)

脱离 Task 即失效的经验切片。通过 tags 与 Task 软关联。具备权重与生命周期。

````markdown
---
id: info_cors_decision
type: info
tags: [auth, api, config]
lifecycle: hot           # hot | cold (后台脚本控制)
weight: decision         # default | decision | failure_patch (AI/Harness控制)
timestamp: "2026-05-01T10:15:00Z"
---
# CORS 跨域配置决策

**背景:** 本地联调时出现预检请求拦截。
**决策 [decision]:** 
不要在每个路由单独配跨域，统一在 Gateway 层的 Nginx 配置 `Access-Control-Allow-Origin: *` (仅开发环境)。
````

### 3.4 Plane: 全局态势感知 (.plane.yaml)

Agent 每次醒来时（Session Start）根据上下文动态生成的全局视窗。它包含了指向外部 KB 的钥匙——认知缺口 (cognitive_gaps)。

```yaml
session_start: "2026-05-01T10:00:00Z"
current_focus: 
  task_id: task_user_auth
  status: "Auth 中间件开发中"
hot_info_context:
  - id: info_cors_decision
    match_tags: [auth, config]
    weight: decision
cognitive_gaps:
  - "Next.js 14 中最新的 Middleware 路由匹配规则是什么？" # 触发对 KB 的检索
```

## 4. 核心系统机制 (Core Mechanisms)

### 4.1 认知蒸馏循环 (Knowledge Distillation Loop)

  1. 暴露缺口： Agent 在执行时发现知识盲区，将问题写入 .plane.yaml 的 cognitive_gaps。
  2. 沙盒检索： Agent 调用工具（如 /search_kb）查询外部向量数据库，获取海量原始长文本。
  3. 提炼内化： Agent 在内存中阅读提取关键逻辑，抛弃无关文字，生成一份高信噪比的 Info（打上对应 Tag），存入 info/ 目录。
  4. 重新聚焦： 新知识被 Plane 挂载，Agent 继续执行。

### 4.2 三级短路 Harness 与失败补丁 (3-Tier Harness Validation)

当 Agent 更新 Task 的 Todo 列表（- [x]）时触发外置 Harness 进程，防止 Agent 陷入死循环：

  * Tier 1 (机械状态检查): 解析 task.md，若存在未勾选的 - [ ]，直接阻断，要求 Agent 继续执行。
  * Tier 2 (严格指标验证): 运行 requirements 中的 validator 脚本（如单元测试）。若报错，进入失败补丁（Failure Patch）流。
  * Tier 3 (语义画面对齐): 调用高级 LLM 独立校验。对比当前产出与 harness.picture 的自然语言描述是否一致。

反哺机制 (Failure Patch): Harness 校验失败不只是报错，而是生成一个 weight: failure_patch 的高优先级 Info 文件强制注入下一轮的 Plane 中，确保 Agent 确切知道“我错在哪”。

### 4.3 被动冷热垃圾回收 (External GC)

减轻 AI 负担，防止上下文污染。由底层的独立脚本（Cron/Node.js）定期执行：

  1. 监控 status: completed 的 Task。
  2. 将该 Task 独占关联的所有 Info 文件，其 YAML 标记修改为 lifecycle: cold。
  3. 超时机制：updated_at 超过 7 天且近期 Plane 未挂载的普通 Info，自动降温。

### 4.4 游离想法的隔离 (Global Inbox)

遇到与当前任务（Plane）完全无关的 Bug 或灵感时：

  1. Agent 绝不原地创建新 Task（防止打断当前认知连贯性）。
  2. Agent 采用极简格式 append 到 inbox.md。
  3. 系统在特定节点（如新会话开启、每周总结）引导用户清空 Inbox。

## 5. 预期系统优势

通过实施这套蓝图，系统将实现：

  1. 极度高能效的上下文： 喂给 LLM 的永远是被浓缩、被目标过滤过的核心状态，极大降低 Token 消耗和幻觉率。
  2. 工程级的鲁棒性： 外部的 Harness 打断了 Agent 可能产生的逻辑死循环，使其具备了“自我纠错”的系统级保障。
  3. 完全透明的掌控感： 没有任何黑盒数据库。开发者可以用 VS Code 随时打开 .mem0ress/，像阅读项目的源代码一样阅读 AI 的“心智状态”。
