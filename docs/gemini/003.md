这是一个极具前瞻性的架构构想。为了彻底避免未来数据的“熵增”与混乱，我们需要在**物理极简**的前提下，引入**领域驱动设计（DDD）**的思想来规范数据模型。

结合你的构想，我将系统模型扩展为 **Task（任务树）、Info（知识库）、Session（会话流）、Plane（瞬态位面）** 四大核心实体。

*   **为什么要引入 Session？** 传统记忆系统的混乱源于“原始对话记录”和“提炼后的知识”混杂。`Session` 负责记录不可变的对话流水账（日志），而 `Info` 负责沉淀经过 AI 提炼的纯粹知识（状态）。
*   **如何处理 Todo？** 放弃为每一个细碎的 Todo 创建文件，而是通过给 Task 增加 `scale (goal | task | todo)` 维度，在单一体系内解决层级问题。

以下是 `mem0ress` 的完整数据模型设计与 Python 核心落地代码。

---

### 一、 核心数据模型设计 (The Schemas)

系统包含 3 种持久化实体和 1 种瞬态实体。所有的持久化文件采用严格的 `YAML Frontmatter + Markdown` 格式。

#### 1. Task (目标与执行节点) - `tasks/` 目录
统一管理从宏观目标到微观行动的所有节点。
*   **Scale 维度:** `goal` (长期目标) -> `task` (具体任务) -> `todo` (单一动作)。
*   **驱动核心:** 任何非 todo 级别的节点，必须拥有 `picture` (画面验收标准)。

```markdown
---
id: task_b7f9a
type: task
scale: task              # goal | task | todo
status: in-progress      # backlog | in-progress | blocked | done | archived
tags: [auth, backend, security]
picture: "用户在 JWT 过期后，系统能利用 Refresh Token 无感续期，不阻断当前请求"
parent_id: task_goal_1   # 向上链接，构建 Task Forest
dependencies:[]         # 阻塞当前任务的其他 task_id
evidence_score: 1        # 0-5 分制
---
# JWT 无感刷新机制设计

- [x] todo_1: 编写 Refresh Token 生成逻辑
- [ ] todo_2: Axios 响应拦截器处理 401 自动重发
```

#### 2. Info (提炼后的记忆与知识) - `info/` 目录
纯粹的上下文、Bug 记录、架构决策。不包含任何执行状态。
*   **Lifecycle 维度:** `hot` (当前强相关) -> `warm` (近期可能用到) -> `cold` (历史归档)。

```markdown
---
id: info_k3m8p
type: info
lifecycle: hot
tags:[auth, jwt, bug]
source: sess_0501_morning  # 信息来源的会话ID（溯源）
created_at: 2026-05-01T10:15:00Z
---
# Axios 拦截器死循环 Bug 记录

**现象:** 在 401 拦截中如果不判断请求 URL，会导致 refresh 接口本身 401 时发生无限死循环。
**决策:** 必须在拦截器中忽略 `/api/auth/refresh` 路径。
```

#### 3. Session (不可变的时间流) - `sessions/` 目录
AI 与用户的交互切片，按时间切分（如每天或每次唤醒一个文件）。它作为底层日志存在，防止 AI "失忆"或"过度提炼丢失细节"。

```markdown
---
id: sess_0501_morning
type: session
timestamp: 2026-05-01T09:00:00Z
summary: "排查 JWT 刷新死循环问题，并确立解决方案"
tags: [auth, debug]
---
# 会话流日志
[09:01 User]: 我发现前端不停在发请求，页面卡死了。
[09:02 AI]: 查看了 Network，是 401 拦截器死循环。原因是没有排除 refresh 接口。
[09:05 AI]: *Action* -> 提取此教训到 `info_k3m8p`。
```

#### 4. Plane (瞬态视窗) - `.plane.yaml`
在当前目录下动态生成，供 AI 一次性读取当前上下文。**每次 Session 开始时计算生成。**

### 二、 Python 落地实现 (代码实现)

为了避免未来格式混乱，我们使用 `Pydantic` 进行严格的 Schema 校验，并提供底层的读写引擎。

首先安装依赖：`pip install pydantic pyyaml`

#### 1. 数据模型定义 (`models.py`)

```python
from pydantic import BaseModel, Field
from typing import List, Optional, Literal
from datetime import datetime

class BaseEntity(BaseModel):
    id: str
    type: Literal["task", "info", "session"]
    tags: List[str] = Field(default_factory=list)
    created_at: datetime = Field(default_factory=datetime.utcnow)
    updated_at: datetime = Field(default_factory=datetime.utcnow)

class Task(BaseEntity):
    type: Literal["task"] = "task"
    scale: Literal["goal", "task", "todo"]
    status: Literal["backlog", "in-progress", "blocked", "done", "archived"]
    picture: Optional[str] = None
    parent_id: Optional[str] = None
    dependencies: List[str] = Field(default_factory=list)
    evidence_score: int = 0

class Info(BaseEntity):
    type: Literal["info"] = "info"
    lifecycle: Literal["hot", "warm", "cold"] = "hot"
    source: Optional[str] = None  # 对应的 session_id

class Session(BaseEntity):
    type: Literal["session"] = "session"
    summary: str

class Plane(BaseModel):
    session_start: datetime
    active_tasks: List[Task]
    hot_context: List[Info]
```

#### 2. 系统核心引擎 (`mem0ress_engine.py`)

这个引擎负责 Markdown 文件的解析、反序列化以及计算生成 `.plane.yaml`。

```python
import os
import yaml
import re
from pathlib import Path
from datetime import datetime
from models import Task, Info, Session, Plane

class Mem0ressManager:
    def __init__(self, base_dir=".mem0ress"):
        self.base_dir = Path(base_dir)
        self.dirs = {
            "task": self.base_dir / "tasks",
            "info": self.base_dir / "info",
            "session": self.base_dir / "sessions"
        }
        self._init_fs()

    def _init_fs(self):
        """初始化扁平化物理目录结构"""
        for dir_path in self.dirs.values():
            dir_path.mkdir(parents=True, exist_ok=True)

    def _parse_md(self, filepath: Path) -> dict:
        """解析 Markdown 文件，提取 YAML Frontmatter"""
        content = filepath.read_text(encoding="utf-8")
        match = re.match(r"^---\n(.*?)\n---\n(.*)", content, re.DOTALL)
        if not match:
            raise ValueError(f"Invalid format in {filepath}")
       
        frontmatter = yaml.safe_load(match.group(1))
        # 我们还可以保留 markdown 正文以供提取
        frontmatter["_content"] = match.group(2).strip()
        return frontmatter

    def save_entity(self, entity_model, content: str):
        """保存实体为 MD 文件"""
        entity_dict = entity_model.model_dump(exclude={"_content"})
        # 处理时间格式化
        for k, v in entity_dict.items():
            if isinstance(v, datetime):
                entity_dict[k] = v.isoformat() + "Z"

        yaml_str = yaml.dump(entity_dict, allow_unicode=True, sort_keys=False)
        file_content = f"---\n{yaml_str}---\n{content}\n"
       
        dir_path = self.dirs[entity_model.type]
        file_path = dir_path / f"{entity_model.id}.md"
        file_path.write_text(file_content, encoding="utf-8")

    def load_all_tasks(self) -> List[Task]:
        tasks = []
        for file in self.dirs["task"].glob("*.md"):
            data = self._parse_md(file)
            data.pop("_content", None)
            tasks.append(Task(**data))
        return tasks

    def load_all_infos(self) -> List[Info]:
        infos = []
        for file in self.dirs["info"].glob("*.md"):
            data = self._parse_md(file)
            data.pop("_content", None)
            infos.append(Info(**data))
        return infos

    def generate_plane(self):
        """核心机制：动态生成瞬态视窗"""
        print("Calculating transient plane...")
       
        # 1. 提取所有进行中/被阻塞的任务
        all_tasks = self.load_all_tasks()
        active_tasks = [t for t in all_tasks if t.status in["in-progress", "blocked"]]
       
        # 2. 提取当前任务关联的所有 tags
        active_tags = set()
        for t in active_tasks:
            active_tags.update(t.tags)
           
        # 3. 提取所有 Lifecycle 为 Hot/Warm，且 Tag 命中的 Info
        all_infos = self.load_all_infos()
        hot_context =[
            info for info in all_infos
            if info.lifecycle in ["hot", "warm"] and set(info.tags).intersection(active_tags)
        ]

        # 4. 构建并保存 Plane
        plane = Plane(
            session_start=datetime.utcnow(),
            active_tasks=active_tasks,
            hot_context=hot_context
        )
       
        plane_dict = plane.model_dump()
        plane_path = self.base_dir / ".plane.yaml"
        with open(plane_path, "w", encoding="utf-8") as f:
            yaml.dump(plane_dict, f, allow_unicode=True, sort_keys=False)
           
        print(f"Plane generated at {plane_path}. Found {len(active_tasks)} active tasks and {len(hot_context)} hot contexts.")
```

#### 3. 测试与运行驱动 (Usage Example)

```python
if __name__ == "__main__":
    mem = Mem0ressManager()

    # 1. AI 决定创建一个进行中的 Task
    new_task = Task(
        id="task_001",
        scale="task",
        status="in-progress",
        tags=["frontend", "react", "performance"],
        picture="首屏加载时间降至 1s 以内"
    )
    mem.save_entity(new_task, "# 优化首页加载\n- [ ] 分析 bundle 大小\n- [ ] 懒加载图片")

    # 2. AI 在之前的 Session 中提取了一条核心知识 (Info)
    new_info = Info(
        id="info_001",
        lifecycle="hot",
        tags=["react", "performance", "vite"],
        source="sess_001"
    )
    mem.save_entity(new_info, "# Vite 拆包策略\n不要把所有的 node_modules 打包成一个 vendor，需要按照路由动态拆分。")

    # 3. 创建一个不相关的冷知识（会被系统忽略）
    cold_info = Info(
        id="info_002",
        lifecycle="cold",
        tags=["react", "performance"],
    )
    mem.save_entity(cold_info, "历史上的一个老方案（已废弃）")

    # 4. Session Start: AI 唤醒，自动生成 Plane
    mem.generate_plane()
```

### 三、 系统的运行节律 (Operating Rhythm)

有了上述模型和代码，`mem0ress` 的运转不再依赖人类的手动整理，而是形成了一套 **AI 自主节律**：

1.  **Awake (唤醒):** AI 启动，调用 `generate_plane()`。系统根据当前 `in-progress` 的 Tasks，利用 Tag 交集和热度筛选，在几毫秒内生成极简的 `.plane.yaml`。
2.  **Act (行动):** AI 读取 `.plane.yaml`（只有几百个 Token），明确自己当前的 `Picture` 和相关的 `Hot Info`，开始写代码或分析问题。
3.  **Distill (提炼):** 在交互过程中，产生的新上下文自动作为 `.md` 写入 `sessions/`。如果发现关键 Bug 或架构决策，AI 调用工具将其提取为一个新的 `Info`，默认状态设为 `hot`。
4.  **Achieve & Decay (达成与衰减):**
    *   当收集到足够证据（`evidence_score` 满足），AI 将 Task 标记为 `done`。
    *   触发钩子脚本：找到该 Task 专属的 `hot` Info，将其降级为 `cold`。
    *   下一次唤醒时，`.plane.yaml` 将彻底刷新，不留一丝垃圾。

通过强类型的 Pydantic 模型约束元数据，配合 Markdown 的高灵活性，这个系统既保证了**计算机读取的确定性**，又保留了**人类阅读的连贯性**。这是一套真正抗腐化的记忆引擎。
